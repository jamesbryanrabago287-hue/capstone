Purpose of the demonstration

Show how a student selects symptoms and follow-up answers, receives a preliminary next action, and can optionally send a summary to the clinic. Ask clinic personnel to revise the questions, decision criteria and student advice. Do not represent provisional rules as clinically validated.

Short presenter script

“This is our working prototype. The decision rules are provisional. We would like your guidance on what questions to ask and when each result should advise monitoring, clinic consultation or more urgent care. Today we are using fictional cases.”

  1. Compare D01 (monitoring/self-care software branch) and D02 (clinic software branch).
  2. Show D04: an explicit warning interrupts the process; submission is optional and does not dispatch help.
  3. Show D06/D07: foot pain and unlisted symptoms currently need human review.
  4. Compare D01/D08 and ask whether the duration restriction is appropriate.
  5. If showing submission, use DEMO STUDENT / DEMO-CLINIC-01 and fictional details only. The materials below do not create records.
  6. Show staff review, identity verification and a basic consultation. Get feedback on the actual workflow.

Ask the reviewer to record the expected clinical action before revealing the software output. These pages do not save reviewer entries to the clinic database. Print or save as PDF to retain feedback. If your team manually saves demo patient records, track them for authorized cleanup; the pack itself does not seed or delete data.

Provisional rules to discuss

  • Adult-only self-care and the deliberately narrow under-24-hour / mild / improving eligibility.
  • Restricted self-care patterns, broad risk groups and grouped warning questions.
  • Uncertain or unlisted symptoms and how unnecessary referrals can be reduced safely.
  • Local clinic contacts, hours and referral routes, which need confirmation.
  • Optional local AI interpretation; answer choices work without Ollama.
